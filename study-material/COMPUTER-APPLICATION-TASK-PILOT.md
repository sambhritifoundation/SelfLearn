# Diploma Chapter 1: task-first review pilot

Scope: the five existing Diploma Chapter 1 topics (internal chapter 11) and its final assignment. Other chapters retain their deployed design.

Learner sequence: task name → example of the finished result → required tools → short action steps with visible checkboxes → show the result. Existing explanation, reference pictures and trainer quality criteria remain available in collapsed help panels. Practice questions and the chapter exam remain accessible.

Reuse: existing topic IDs, notes, image paths, exam set and quality criteria. The lock-screen asset is reused in the first result example; the original reference pictures remain in each lesson's explanation. Folder and note previews are labelled illustrative output, not simulated controls or actual readings from the learner's computer.

Progress: checkboxes are self-reported actions, separate from quiz mastery and trainer approval. They use the existing learner-profile key helper and browser storage. Failure to save displays a message. Reset clears only the current task's ticks and does not touch user files, original practical progress or exam results.

Review with learners: can they name the expected output without opening an explanation? Can they start the first action? Do the visual and checked steps agree? Can the trainer verify the actual result? Is there a step that needs a screenshot or further breakdown?

After approval, migrate chapter by chapter using the same activity fields (stable ID, bilingual task title, output preview, prerequisites, atomic steps, success check and help). Reuse each chapter's assets and lesson text. Generalise the renderer's chapter binding before enabling more chapters, and namespace future activity IDs; version stored checklists if their meaning or step order changes. Do not enable the layout elsewhere until the user approves the pilot.
